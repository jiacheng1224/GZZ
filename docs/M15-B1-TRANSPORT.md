# M15-B1 房间存储与 HTTP 权威适配器

版本：`1.8.0-r6.m15b1`

依赖：M14 联机协议、M15-A 权威房间状态机

## 目标

将纯 TypeScript 房间状态机接入 Cloudflare Worker 和 D1，使房间状态可以跨请求保存，并通过同源 JSON API 完成创建、加入、准备、心跳、命令、断线恢复与再战。

M15-B1 交付可靠的请求／响应权威链路。普通 Worker 无法保证同一房间的 WebSocket 始终落在同一实例，因此本增量不以进程内 Map 冒充生产实时服务；长连接和房间广播将在托管环境提供 Durable Object 或等价单写者能力后接入。

## API

### 创建房间

`POST /api/rooms`

请求：`{ "seed": "可选局面种子" }`

响应包含公开房间视图，以及只返回一次的房主 `session.token`。

### 加入房间

`POST /api/rooms/join`

请求：`{ "inviteCode": "六位邀请码" }`

响应包含公开房间视图，以及只返回一次的访客 `session.token`。

### 房间动作

`POST /api/rooms/:roomId/actions`

请求必须使用 `Authorization: Bearer <token>`。服务端先计算 SHA-256 摘要并由摘要反查席位，不信任客户端提交的玩家身份。

支持动作：

- `{ "action": "ready", "ready": true }`；
- `{ "action": "heartbeat" }`；
- `{ "action": "disconnect" }`；
- `{ "action": "reconnect" }`；
- `{ "action": "command", "envelope": CommandEnvelope }`；
- `{ "action": "rematch" }`。

所有响应设置 `Cache-Control: no-store`。请求体上限为 64 KiB。

## 凭据安全

- 令牌使用 32 字节密码学随机数并编码为 Base64URL；
- 数据库只保存 SHA-256 摘要，明文令牌仅在创建或加入响应中出现一次；
- 结构化日志只记录操作、状态码和耗时，不记录令牌、摘要、手牌或牌堆；
- 无效凭据返回 `401`，过期房间返回 `410`，并发或生命周期冲突返回 `409`。

邀请码用于找到房间，不承担身份认证职责。

## 持久化与并发

`game_rooms` 表保存房间 ID、邀请码、权威状态 JSON、状态、修订号和生命周期时间。每次更新使用：

`WHERE room_id = ? AND revision = ?`

成功后修订号原子加一。并行请求只有一个写入者成功，失败方收到冲突并重新取得最新状态，从而避免最后写入者静默覆盖合法命令。

## 自动化验收

- 创建令牌长度与字符集稳定，数据库序列化结果不含明文令牌；
- 双人加入并准备后生成权威快照；
- 已认证 M14 命令可以推进状态版本；
- 伪造 Bearer 令牌在读取任何玩家快照前被拒绝；
- 断线动作后可使用原令牌恢复；
- 相同修订号的并行写入不能互相覆盖；
- 结构化日志不泄露令牌；超大请求体被拒绝。
