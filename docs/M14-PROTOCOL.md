# M14 版本化命令与状态投影协议

版本：`1.6.0-r6.m14`

核心版本：`1.3.0-r6.m14.protocol`

协议版本：`1`

## 目标

为本地规则核心与后续权威房间服务建立稳定边界。客户端只能提交意图，不能提交或替换规则状态；服务端执行相同的 `applyCommand()`，然后仅返回经过 `projectForPlayer()` 脱敏的状态。

M14 不创建房间、不绑定真实用户、不建立 WebSocket，也不管理断线计时。这些属于 M15。

## 命令信封

`CommandEnvelope` 包含：

- `schemaVersion` 与 `protocolVersion`；
- `roomId`、`playerId` 和客户端版本；
- 全局唯一 `commandId` 幂等键；
- 玩家单调递增 `sequence`；
- 客户端最后确认的 `expectedStateVersion`；
- 唯一可执行内容 `command: GameCommand`。

运行时解码器会重建允许的命令字段。额外附带的 `state`、牌堆、胜者或其他注入字段都会被丢弃，未知命令类型会在进入规则引擎前拒绝。

## 权威处理顺序

1. 校验信封结构、字符串长度和数组上限；
2. 协商协议版本，版本不支持时返回明确升级版本；
3. 核对房间、认证玩家与命令 actor；
4. 检查 `commandId`，相同内容返回 `duplicate`，不同内容返回冲突；
5. 检查玩家命令序号；
6. 检查权威状态版本；
7. 通过 `applyCommand()` 执行规则；
8. 状态版本加一并返回事件增量和玩家投影。

身份或房间核对失败的响应不包含任何快照。乱序、过期状态和规则拒绝可附带已认证玩家的最新脱敏快照，帮助客户端恢复。

## 幂等与冲突

- 首次合法命令返回 `accepted` 并推进一次状态。
- 完全相同的 `commandId` 与内容再次到达时返回 `duplicate`，不重复执行。
- 相同 ID 搭配不同内容返回 `COMMAND_ID_CONFLICT`。
- 被拒绝的命令不消耗玩家序号，客户端可使用相同序号和新的命令 ID 修正后重试。

## 重连

`createReconnectSnapshot()` 返回：

- 当前权威 `stateVersion`；
- 该玩家可提交的 `nextSequence`；
- 最新 `eventCursor`；
- 指定玩家的 `PlayerView`；
- 与命令响应相同的协议和房间标识。

快照不包含对手手牌、任一牌堆顺序、开局种子或 `cardUniverse`。客户端缓存不参与规则判定。

## 自动化验收

- 合法版本化意图由权威状态执行，输入状态不变；
- 客户端伪造状态和额外命令字段无效；
- 重复命令幂等，冲突 ID 明确拒绝；
- 乱序、过期状态、错误协议、错误房间和身份篡改均有稳定错误码；
- 非法规则命令不会推进状态或玩家序号；
- 重连快照与最新接受响应一致且不泄露隐藏信息。

## 后续

M15 将在该协议之上实现房间创建、加入、准备、身份绑定、心跳、断线保留、重连和再战，并建立连续 50 局线上同步基准。
