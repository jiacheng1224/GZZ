# M15-B2 在线房间客户端与增量同步

版本：`1.9.0-r6.m15b2`

核心版本：`1.5.0-r6.m15.sync`

## 目标

在 M15-B1 权威 HTTP API 上提供可使用的浏览器在线流程：创建房间、邀请码加入、双方准备、私密玩家快照、在线棋盘、版本化命令、连接状态、自动同步和刷新恢复。

当前托管能力未声明 Durable Object，因此客户端使用 1.5 秒条件轮询实现近实时同步。服务端以 D1 修订号生成 `ETag`，状态未改变时返回 `304`，避免反复传输完整投影。该方案保证权威性与跨实例一致性，后续可在不修改规则核心和 UI 命令模型的前提下替换为 WebSocket 推送。

## 玩家流程

1. 在对局设置选择“在线房间”；
2. 创建房间并复制六位邀请码，或输入邀请码加入；
3. 双方查看在线、断线保留和准备状态；
4. 双方准备后取得各自的 `ProtocolSnapshot`；
5. 在九条战线和私密手牌视图中提交 M14 `CommandEnvelope`；
6. 对手行动期间自动轮询最新房间修订；
7. 网络恢复或刷新后使用当前标签页保存的会话令牌重新同步；
8. 结束后双方可请求再战。

## 同步模型

- `GET /api/rooms/:roomId`：认证后返回公开房间和当前玩家快照；
- `ETag`／`If-None-Match`：房间修订未变化时返回 `304`；
- 每 15 秒发送一次已认证心跳；
- 命令包含 `commandId`、玩家序号和预期状态版本；
- 网络失败时用完全相同的信封重试一次，由 M14 幂等处理；
- 服务端拒绝过期或乱序命令后，客户端采用返回快照并再次同步；
- 重连快照新增 `nextSequence`，刷新后可以继续正确编号命令。

## 信息边界

- 在线棋盘只读取 `PlayerView`，不接收或保存 `GameState`；
- DOM 只包含查看者手牌、公开战线和公开事件；
- 对手仅显示手牌数量；
- Bearer 令牌保存在当前标签页的 `sessionStorage`，不写入 URL、DOM、日志或长期本地存档；
- 返回设置会保留会话，显式离开才提交断线并清除令牌。

## 棋盘能力

- 手牌选择与战线部署；
- 占旗和补牌；
- 士气、环境和诡计战术；
- 侦察及多步骤战术命令；
- 当前行动方、阶段、回合、连接状态和对手手牌数；
- 结束状态和再战投票。

所有按钮来源于服务端投影的 `legalCommands`，页面不重复判断规则合法性。

## 自动化验收

- API 条件读取返回私密快照和 ETag，未变化修订返回空 `304`；
- 在线入口可以创建房间、显示邀请码并切换准备；
- 页面与公开房间视图均不包含明文会话令牌；
- 协议重连快照包含下一命令序号；
- 105 项单元测试与 19 项 Chromium 流程全部通过；
- 本地双人、AI、教学、回放、战术和结算流程保持可用。
